Architecture

How a debate runs

All agents read from and write to one shared fact sheet. Each fact has an ID, a theme, a direction (bullish, bearish or neutral) and a strength, and every argument has to point back to those IDs.

Evaluation

Both backends reach the same answers

Every scenario ran twice: once on the offline rule-based backend and once live through Semantic Kernel with a Gemini model. The scorecard margins differ because the live model rates facts more decisively, but they land in the same zone each time, so every final recommendation matches.

Guardrails

Rules the code enforces

None of these depend on a prompt. They are checks in the program, so they still hold when a language model gets something wrong. A failed check never crashes a run: the item is dropped and written to an audit log.

Every claim must cite

A claim with no citation, an unknown fact ID, or a number that is not in the cited fact is dropped and logged.

The Judge only sees cited facts

Its input holds just the facts the debaters cited, it has no search tool, and any other ID it produces is stripped. In the Helios run it saw 9 of 16 facts.

The veto is rule-based

Risk tests the whole fact sheet against stated limits and hard-flag disclosures. A model may write the narrative but cannot add or remove a veto.

Risk is independent of the Judge

Risk limits never change how facts are rated for the Judge, so a veto cannot be built into the verdict in advance. A test caught this flaw during development.

Get started

Run it yourself

The offline backend needs no API key. For a live run, set a key for OpenAI, Azure OpenAI or Google Gemini and add --backend sk.

Windows PowerShell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python run_debate.py data/verdant --backend offline
pytest tests -q
macOS or Linux
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python run_debate.py data/verdant --backend offline
pytest tests -q
Live model (PowerShell)
$env:GEMINI_API_KEY="your-key"
$env:GEMINI_MODEL="gemini-3.5-flash-lite"
python run_debate.py data/verdant --backend sk
Try the veto
python run_debate.py data/helios --backend sk --limit leverage_x=1.0

Every run writes a Markdown report and a JSON record with the recommendation, the strongest argument on each side, the Judge's rationale, the Risk review, the scorecard, the full transcript and the audit log.
